## 1. 초기 0.1.0~0.1.1 시험 범위

첫 검증은 사용자가 만든 1:1 오픈채팅방 ‘봇테스트’에서 수행했고, 0.1.1-test는 사용자가 지정한 별도 그룹 오픈채팅방으로 확대해 시험했다. 한 번에 한 방만 연결한다. 연결 코드가 유효한 5분 동안만 새 카카오톡 알림의 마지막 메시지에서 정확한 연결 코드를 검사하며, 일치하지 않은 내용과 이전 메시지는 저장하거나 명령으로 처리하지 않는다.

## 4. 검증과 남은 범위

단위 검사는 한국 날짜·요일 경계, 월말·윤년·개월 주기, 늦은 안내 만료, 일정 수정 시 회차 ID 유지, 명령 입력 검증을 대상으로 한다. 기기 검사는 DB 선점 경쟁, 전송 중 중단 복구, 취소·수정된 일정 차단을 대상으로 한다.

이 시험은 테더링을 유지하고 재부팅·USB 모드 변경·네트워크 단절 시험을 하지 않는다. 화면은 평소 잠금·꺼짐 상태를 유지하고 필요한 UI 설정 때만 사용자 잠금 해제를 요청한다.

기존 디스코드 봇 서버 연동, 공식 일정의 예외 회차, 캐치마인드 그림 경로, 공개 배포용 서명·전체 배포 고지 검사는 후속 단계다. 실제 월드보스·정기 콘텐츠·컬렉션 원본은 아직 등록하지 않는다.

## 8. 0.1.1-test 연결 상태·그룹 알림 수정

증상: 다른 오픈채팅방에 연결 코드를 보내도 앱이 ‘코드 수신 대기’에서 바뀌지 않았다. 코드상 그룹방 이름을 기본 시험 방으로 고정한 제한과 별도로, 실제 isGroupConversation=true 알림에도 방 이름 없이 보낸 사람 이름만 들어오는 형식을 확인했다. 방 이름 입력만 추가한 수정으로는 충분하지 않았다.

수정: 대상 방 이름을 로컬 앱에서 입력하도록 하고, 실제 구조화된 대화 제목과 일반 알림 제목을 구분한다. 방 이름이 없으면 유효한 일회용 코드·새 알림·안정적인 식별 근거·사용자의 로컬 확인으로 연결한다. 다른 방임을 명시하는 구조화된 제목은 거부한다. 과거 알림에 남은 코드는 재연결에 쓰지 않는다.

화면: 알림 권한·수신 서비스·코드 대기/만료/후보·방 연결 확정·답장 준비·응답 실행을 구분하고 변경 이벤트와 초 단위 남은 시간을 반영한다. 마지막 대상 알림 시각을 표시한다. 최근 답장 정보 보관을 카카오 서버 접속 확인으로 표현하지 않는다. 권한은 있지만 서비스가 연결되지 않았으면 앱 재개 시 재연결을 요청한다.

추가 진단: 그룹방의 유효한 코드는 앱까지 도착했고 텍스트 입력·free-form 정보도 있었지만 답장 버튼 소유자가 null·UID -1로 반환돼 검증에서 거부됐다. 시스템 알림의 답장 버튼을 직접 눌러 입력창도 확인했으며 메시지는 전송하지 않았다. 카카오톡 패키지 조회 선언 누락을 보완하자 같은 알림의 소유자가 com.kakao.talk과 실제 UID로 정상 반환되는 것을 비교 확인했다. 소유자·텍스트 입력 검증은 유지한다. 코드를 받았으나 답장 정보를 확보하지 못하면 ‘수신 대기’ 대신 실패 이유를 표시한다.

검증: 단위 검사 24개, 폰 DB·설정·화면·카카오톡 조회 검사 9개 통과, 정적 검사 오류 0건. 별도의 개발용 코드 준비 검사도 통과했다. 화면 검사는 잠금 해제 상태에서 카운트다운이 재진입 없이 바뀌는지 확인했다. 보안 잠금 중에는 화면이 일시정지된다는 시험 선행 조건을 명시했다.

설치한 최종 0.1.1-test APK SHA-256: `a0e8cd96bb18ebf14e867b3f5b6220de40c4faac24b89aaedcd9f98807a7953f`. 생성 파일에 중복 사본이 생기는 오류가 반복돼 Gradle 중간 산출물을 프로젝트별 임시 폴더로 분리하고 최종 APK·보고서만 기존 경로에 복사한다. 시스템 동기화·네트워크 설정은 변경하지 않았다.

### 실제 그룹방 재검증

사용자가 다른 계정에서 현재 코드를 보냈고, 앱을 다시 열지 않아도 ‘코드 수신 · 연결 확인 필요’로 바뀌는 것을 직접 확인했다. 로컬 연결 확인 후 명령 응답을 켰다. 수신자가 !핑 답장, !알림테스트 접수 답장, 약 30초 뒤 예약 알림의 실제 도착을 모두 확인했다. 예약 알림을 기다리는 동안 폰 화면을 끄는 명령을 실행했다.

폰 전송 요청 수락 누계는 기존 5건에서 8건으로 증가했고 실패·결과 불명 항목은 없었다. 현재 연결한 한 방의 응답은 실행 중이고 정기 알림은 OFF다. 장시간 잠금·Doze·재부팅·네트워크 단절까지 통과했다는 뜻으로 확대하지 않는다. 공개 문서에는 실제 그룹방 이름·참여자 이름·연결 코드를 기록하지 않는다.

## 9. 0.2.0-test 다중 방·역할 분리

여러 방의 독립 연결과 역할 선택을 구현하고 폰에 설치했다. 사용자 답변에 따라 실제 방별 역할은 미정으로 유지한다. 초기 역할은 게임 일정 알림·오락·알림+오락이며, 기존 방은 기본 혼합 역할로 기존 파일을 그대로 사용한다. 새 방은 별도 설정·DB를 사용하고 UI 선택과 무관하게 확정 대화 식별자로 수신을 처리한다.

단위 검사 29개, 폰 독립 DB·설정·다중 방 저장 검사 11개 통과. 정적 검사 오류 0건. 기존 방 설정 보존과 READY·응답 ON·정기 발송 OFF 상태 확인. 신규 두 방 실제 답장·역할 밖 명령 차단을 수신자가 확인했다. 추가 시험으로 접수 답장·30초 알림 실제 도착과 COMMAND·TEST 각각의 요청 수락 기록을 교차 확인했다. 상세 요구사항과 결과는 11 다중 방·역할 분리 기획 및 설계에서 관리한다.
