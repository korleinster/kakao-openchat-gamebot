- 사용자 요구사항과 설계 초안 작성, MIT 기준 커밋·원문 보존.
- 로컬 문서·설정 초안·데이터 계약 준비. 운영 일정 데이터는 비어 있고 자동 발송은 OFF.

- 실기기 ADB 확인: Galaxy S20+ (SM-G986N), Android 13 / API 33, One UI 5.1, 카카오톡 26.9.1. USB 구성 rndis,adb. 앱 정보 화면·ADB 스크롤·scrcpy 영상 디코딩 확인 완료.
- 같은 폰이 USB 테더링 용도. 테더링·TetherKit·경로·DNS·Tailscale을 변경하지 않음.

## 4. 증거 양식

기록 필드: test_id, 실행 시각, OS·카카오톡·앱 버전, 잠금·절전 상태, 예정 시각, API 호출 시각, 수신측 실제 표시 시각, 지연, 결과, 비식별 화면·로그 경로.

테스트 결과는 NOT_RUN/PASS/FAIL/INCONCLUSIVE로 구분한다. 앱 로그만 있고 상대 화면 확인이 없으면 전송 도착 시험은 PASS가 아니다. 실제 운영방에 시험 메시지를 보내기 전에 테스트 방을 사용한다.

## 5. Android 폰 직접 조작 준비

ADB로 설치·설정 조회·화면 캡처·입력을, scrcpy로 화면 표시·조작을 검토한다. 최초 USB 디버깅 활성화 및 Mac의 RSA 연결 허용은 폰에서 사용자가 승인해야 한다. 현재는 사용자가 최초 승인을 완료했고 USB 연결·상태 조회·화면 표시·ADB 입력을 확인했다.

USB 디버깅 활성화가 USB 구성을 바꿔 테더링을 잠시 끊을 수 있으므로, 인터넷 연결을 유지해야 하는 현재 상태에서는 사용자에게 영향과 복구 방법을 안내하고 허가 후 진행한다. 대안은 Android 13의 무선 디버깅이지만 같은 네트워크·페어링 가능 여부를 먼저 확인해야 하며, 그 목적의 네트워크 설정 변경은 임의 수행하지 않는다.

폰 재부팅, 테더링 OFF, USB 모드 변경, TetherKit 재시작·종료는 이번 문서 작업에서 수행하지 않는다. 패키지 버전 조회만으로 폰 조작·앱 설치·카카오톡 발송이 완료됐다고 표시하지 않는다.
