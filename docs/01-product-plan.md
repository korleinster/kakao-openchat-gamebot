## 1. 목적과 기대효과

리니지2M 오픈채팅방에서 월드보스, 정기 콘텐츠, 기간제 컬렉션의 일정을 놓치지 않도록 안내하고 짧게 참여할 수 있는 오락 기능을 제공한다. 특정 안드로이드 폰의 카카오톡 계정을 통해 지정한 방에 발송한다.

전체 흐름: 운영자가 앱에서 방·일정을 설정 → 앱이 다음 알림을 계산 → 시작 5분 전 또는 아침에 지정 방으로 발송 → 참여자는 채팅 명령으로 일정 조회·뽑기 참여.

## 2. 확정된 요구사항

| ID | 항목 | 사용자 확정 내용 |
| --- | --- | --- |
| REQ-01 | 대상 | 리니지2M, 카카오톡 오픈채팅방 |
| REQ-02 | 월드보스 | 시작 5분 전에 알림 |
| REQ-03 | 정기 콘텐츠 | 시작 5분 전에 알림 |

| REQ-05 | 기간제 컬렉션 | 게임 공통 갱신 일정. 2개월·4개월 등 여러 종류. 실제 자료는 사용자가 추후 제공 |
| REQ-06 | 오락 | 뽑기, 캐치마인드 등 가벼운 참여형 기능 희망 |
| REQ-07 | 개발 방향 | MIT 후보의 필요한 부분을 참고·재사용한 독립 앱 개발 준비 및 보완 설계 |
| REQ-08 | 문서 관리 | 공부용 → AI → 카카오톡 봇 하위 페이지별 관리 |

월드보스·정기 콘텐츠의 시작 시각 알림과 1분 전 알림은 이번 확정 요구사항에 포함하지 않는다. 기존 디스코드 봇의 모든 메시지를 그대로 전달하지 않는다.

## 3. 1차 범위 제안

| 기능 | 범위 | 선행 조건 |
| --- | --- | --- |
| 지정 방 연결 | 테스트 방을 선택·확인하고 운영 대상 1개 방을 활성화 | 방 식별·답장 기능 시험 |
| 일정 알림 | 월드보스·정기 콘텐츠 5분 전, 아침 일정 한 건으로 묶기 | 실제 일정과 아침 시각 입력 |
| 컬렉션 | 종류별 기준일·주기·공식 회차 입력 및 계산 | 사용자 자료 수령. 미등록 항목은 발송하지 않음 |
| 조회 | !오늘, !월보, !정기, !컬렉션, !도움말 | 설정된 데이터만 사용 |
| 오락 | 이름 지정 또는 참가 신청을 받는 뽑기, 주사위 | 텍스트 수신·전송 검증 |
| 운영 화면 | 실행 상태, 다음 알림, 연결 대기, 실패·미확인 이력 | 전송 상태 구분 구현 |

캐치마인드는 2차 설계 후보로 유지한다. 그림 업로드·전송 경로를 검증하기 전에는 구현 확정으로 표시하지 않는다. AI 대화와 로컬 LLM은 1차 범위 제안에서 제외한다.

## 4. 앱의 최초 상태와 화면

최초 설치: 자동 발송 OFF, 연결된 방 없음, 실제 일정 없음, 아침 발송 시각 07:00 (사용자 확정), 발송 활성화 전. 예시 데이터는 운영 일정과 구분하고 발송 비활성 상태로 유지한다.

| 화면 | 보이는 정보 | 주요 조작 |
| --- | --- | --- |
| 홈 | 실행 중/연결 대기/권한 필요, 다음 알림, 마지막 전송 결과 | 시작·일시정지, 연결 상태 확인 |
| 대상 방 | 표시 이름, 확인된 식별 정보, 최근 연결 시각 | 방 연결, 테스트 메시지 미리보기·수동 발송 |
| 일정 | 종류, 다음 시작 시각, 출처·확인일, 활성 여부 | 등록·수정·비활성화 |
| 아침 안내 | 발송 시각, 포함 기능, 미리보기 | 시각 저장 후 활성화 |
| 전송 기록 | 예정/요청됨/미확인/실패/만료 | 원인 확인. 자동 중복 재전송 금지 |

운영 설정 변경은 앱 안에서만 허용하는 1차 설계안이다. 채팅 닉네임만으로 관리자 권한을 부여하지 않는다.

## 5. 아직 확정하지 않은 값

- 폰은 Galaxy S20+ / Android 13 / One UI 5.1로 사용자 확인. 카카오톡 정확한 버전과 일상 사용 범위는 확인 필요.
- 봇 전용 계정·기기 여부, 실제 대상 방의 연결 정보.
- 아침 시각은 07:00으로 사용자 확정. 일정이 없는 날의 안내 여부는 확인 필요.
- 월드보스·정기 콘텐츠 실제 목록, 서버·이벤트 예외, 원본 데이터 연결 방식.
- 컬렉션별 기준일·갱신일·2개월/4개월의 정의와 사전 안내 시점.
- GitHub 저장소 이름·공개 범위, 앱 이름·배포 방식.

미정 값은 추정해 운영값으로 등록하지 않는다. 이후 결정은 결정 기록의 해당 항목을 갱신한다.
