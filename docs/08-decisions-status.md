## 2. 설계 제안

- ADR-01: Kotlin 앱 + 로컬 영속 DB + Android 알람 + 카카오톡 알림 답장 어댑터.
- ADR-02: 방 이름 단독 매칭 금지, 충돌·식별 근거 부족 시 발송 차단.
- ADR-03: 전송 요청 수락·실패·결과 불명·실제 도착 확인을 구분.
- ADR-04: 재시작 후 실제 활성 알림으로만 답장 정보 재확보. 없으면 대기.
- ADR-05: 1차는 특정 한 방과 텍스트 일정·뽑기. AI 대화·직접 이미지 전송은 후순위.
- ADR-06: 5분 전 알림 지연 허용 60초, 아침 안내 복구 유예 10분은 검증 전 제안값.
- ADR-07: 설정 변경은 로컬 앱에서 수행. 닉네임 기반 관리자 인증은 사용하지 않음.

위 제안은 문서 작성 권한을 모든 운영 정책의 사용자 확정으로 확대하지 않는다. 구현 중 근거·실기기 제약에 따라 수정하고 변경 이유를 기록한다.

## 5. 문서 운영

노션을 사용자 검토·기획의 기준 문서로 사용하고 로컬 docs를 개발 참조 사본으로 둔다. 기능 범위·시각·예외·수용 기준을 바꾸면 관련 페이지와 결정 기록을 함께 갱신한다. 구현 PR에는 실제 변경과 검증 증거를 연결한다.

작성 완료, 코드 구현, 빌드 통과, 실기기 확인, 운영 적용을 각각 별도 상태로 관리한다. 현재 Android 시험 앱 구현·빌드·설치를 완료했다. 실제 카카오톡 발송·운영 적용 상태는 10 구현 현황·테스트 기록에서 구분한다.
